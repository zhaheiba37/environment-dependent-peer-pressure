# Environment-dependent peer pressure with Q-learning

Simulation code for **Environment-dependent peer pressure in spatial public goods games with reinforcement learning**.

The project implements the model and parameter scans used in the paper. Simulation results are generated by running the code. 中文说明见 [README_zh.md](README_zh.md).

## Installation

Use Python 3.10–3.12. From the project directory:

```bash
python -m pip install -r requirements.txt
```

## Quick start

```bash
python run.py --config examples/quickstart.json --output outputs/demo
```

This example runs a 10×10 lattice for 100 MCS. The first run compiles the Numba kernel. Use a new output directory for each execution.

## Model

Individuals occupy an L×L periodic square lattice. Each interaction group consists of a focal individual and its four nearest neighbors. Actions are encoded as C=1 and D=0. Initially, each individual chooses C or D with equal probability, and all Q-values are zero.

One MCS consists of L² group interactions, with focal individuals sampled uniformly with replacement. All five group members choose actions and update their Q-tables in each interaction:

1. Count cooperators in the current group. The environment is G when nC≥T and B otherwise.
2. Determine each member's current learning state. Joint states are CG, CB, DG and DB.
3. Select actions using the epsilon-greedy rule. Exploration and ties between Q-values use uniform random selection.
4. Implement the five actions simultaneously and reassess the same group's environment.
5. Calculate rewards and next states, then update each member's Q-table.

The basic payoff is `pi = r*nC/5 - action`, with cooperation cost 1. Under environment-dependent pressure, defectors lose `beta*nC` in G and cooperators lose `beta*(5-nC)` in B. Other individuals receive no pressure. Each update uses the payoff from that group interaction.

The Q-learning update is:

```text
Q(s,a) += alpha * (reward + gamma*max(Q(next_s,:)) - Q(s,a))
```

The environment-independent control applies pressure from all opposite-action group members. The learning state can include both behavior and environment (`joint`), behavior alone (`behavior`), or environment alone (`environment`).

## Paper experiments

Defaults are L=100, r=3.5, T=3, beta=0.1, alpha=0.1, gamma=0.9 and epsilon=0.01. Each run lasts 1,000,000 MCS; the final cooperation level is the mean over the last 100,000 MCS. Progress is printed every 10,000 MCS.

Generate a configuration file and run the selected experiment:

```bash
python make_configs.py fig3-4 --output fig34.json
python run.py --config fig34.json --output outputs/fig34 --workers 3
```

| Preset | Parameter settings |
| --- | --- |
| fig2a | r=2.8:0.1:5.0; beta=0,0.05,0.1,0.15,0.2 |
| fig2b | r=3.2,3.4,3.6,3.8,4.0; beta=0:0.01:0.2 |
| fig3-4 | r=3.5, T=3; beta=0,0.1,0.2 |
| fig5a | r=3.5; T=0,1,2,3,4,5; beta=0,0.05,0.1,0.15,0.2 |
| fig5b | r=3.5; T=1,2,3,4; beta=0:0.01:0.2 |
| fig6a | T=3; r=2.9:0.1:5.0; beta=0.1,0.2; both pressure rules, joint states |
| fig6b | T=3, beta=0.1; r=2.9:0.1:5.0; joint, behavior-only and environment-only states |

Unspecified parameters use the defaults. The notation start:step:end includes both endpoints. By default, the configuration generator creates one independent run per parameter point. Add `--repeats 5` to the `make_configs.py` command for five runs with different seeds per point. `--workers` sets the number of independent simulations run in parallel.

For points requiring longer evolution, edit `examples/long_run.json` and run:

```bash
python run.py --config examples/long_run.json --output outputs/long_run
```

This starts a fresh run lasting 100 million MCS and averages over the last 10 million MCS. Inspect the trajectory when deciding whether a longer run is needed.

## Custom parameters

Edit a JSON configuration file. A JSON object defines one run; a list defines multiple runs. Omitted fields use the defaults in `run.py`.

| Field | Meaning |
| --- | --- |
| length, r, threshold, beta | Lattice size, synergy factor, environmental threshold and pressure intensity |
| alpha, gamma, epsilon | Learning rate, discount factor and exploration probability |
| initial_cooperation | Initial probability of cooperation; default 0.5 |
| pressure | `dependent` or `independent` |
| state | `joint`, `behavior` or `environment` |
| mcs, tail | Total duration and final averaging window |
| seed | Random seed for initialization and interaction events |
| progress_every | Progress-report interval in MCS |
| record_every | Trajectory-recording interval in MCS; default 1 |
| snapshots | Comma-separated snapshot times, e.g. `0,3000,50000,1000000` |

Each execution starts with a new random lattice and zero Q-values. Increasing `record_every` reduces output size; the final mean still uses every MCS in the averaging window. Recorded trajectory rows are individual MCS observations.

## Outputs

Each `run_XXXX/` directory contains:

- `metadata.json`: parameters, seed, software versions, source hashes and run status.
- `trajectory.csv`: MCS, cooperation fraction, state visit counts and state-action advantages. Row 0 records the initial cooperation fraction.
- `actions_mcs_N.npy`: spatial snapshots at the requested times within the run (0=D, 1=C).
- `final_state.npz`: final actions and Q-tables; the action axis is ordered D,C.
- `summary.json`: cooperation mean and temporal standard deviation over the final averaging window.

State advantages are the mean `Q(C)-Q(D)` over actual visits during the recorded MCS, evaluated before the Q-updates. Repeated visits count separately; unvisited states have `nan`. State order is recorded in metadata. The temporal standard deviation describes fluctuations within a run.
